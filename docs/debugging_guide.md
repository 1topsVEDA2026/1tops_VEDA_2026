## 3. Understanding the Trace Comparison Mechanism

The comparison engine (`spike_verify/compare_spike_rtl.py`) compares the Spike ISS execution log against the RTL retirement trace.

### Spike Log Format (`--log-commits`)
```text
core   0: 3 0x80000018 (0x400015b7) x11 0x40001000
core   0: 3 0x8000001c (0x10058593) x11 0x40001100
```
- `0x80000018`: Program counter (PC)
- `(0x400015b7)`: Executed instruction word
- `x11 0x40001000`: Destination register (`rd`) and committed writeback value

### RTL Log Format (Generated by `rv32im_riscv_dv_tb.sv`)
```text
core   0: 0x80000018 (0x400015b7) x11 0x40001000
core   0: 0x8000001c (0x10058593) x11 0x40001100
```
Generated using:
```systemverilog
always_ff @(posedge clk) begin
    if (rst_n && !u_dut.stall_MW) begin
        if (u_dut.rf_en_MW && u_dut.rd_addr_MW != 5'd0)
            $fwrite(trace_fd, "core   0: 0x%08h (0x%08h) x%0d 0x%08h\n",
                    u_dut.pc_out_MW, retired_instr, u_dut.rd_addr_MW, u_dut.wdata);
        else if (u_dut.wr_en_MW)
            $fwrite(trace_fd, "core   0: 0x%08h (0x%08h) mem 0x%08h\n",
                    u_dut.pc_out_MW, retired_instr, dmem_awaddr);
        else if (u_dut.pc_out_MW != prev_pc)
            $fwrite(trace_fd, "core   0: 0x%08h (0x%08h)\n",
                    u_dut.pc_out_MW, retired_instr);
        prev_pc <= u_dut.pc_out_MW;
    end
end
```

## 4. Key Bugs Identified & Resolved

### 1. Base Address Alignment (`RESET_PC = 0x8000_0000`)
- **Issue**: Spike ISS boots via trampoline into DRAM base `0x8000_0000`, while the RTL previously booted at `0x0000_0000`. In randomized RISCV-DV code, pointer calculations using `AUIPC` (e.g. kernel stack pointer setup) differed by `0x8000_0000`, which subsequent arithmetic instructions used as arithmetic operands, causing mathematical divergence.
- **Fix**: Added a parameter `RESET_PC` to `rv32_core_top` with default `32'h0000_0000`. In the RISCV-DV testbench, `RESET_PC` is set to `32'h8000_0000`. Both Spike and RTL now execute at identical PCs, resolving pointer divergence.

### 2. Multi-Cycle Retirement Duplicate Logging
- **Issue**: When an instruction was stalled in the MW stage (due to MDU calculation in DE, or AXI4 slave wait states), the testbench previously logged the stalled instruction on every clock cycle, causing trace desynchronization.
- **Fix**: Gated the RTL retirement logger with `if (rst_n && !u_dut.stall_MW)`. Instructions are now logged only on their retirement completion cycle.

### 3. AXI4 DMEM Master Handshake Latching in `DM_IDLE`
- **Issue**: When a load instruction in `DM_IDLE` saw an immediate `ARREADY = 1` from the slave, but `RVALID = 0`, the FSM transitioned to `DM_RD` without latching `dm_ar_done = 1`. In `DM_RD`, the master illegally drove `ARVALID = 1` a second time, violating AXI4 protocol and triggering SVA assertions.
- **Fix**: Updated `rv32_core_top.sv` so that handshakes occurring during `DM_IDLE` are captured (`dm_ar_done <= dmem_arvalid && dmem_arready;`, `dm_aw_done <= ...`, `dm_w_done <= ...`).

### 4. Hex Memory File Addressing & Conversion
- **Issue**: Verilog `$readmemh` into word arrays requires word indices (`@00000000`, `@00002000`), whereas objcopy outputs byte addresses. A previous `sed` script only replaced `@80000000` with `@00000000`, leaving data section addresses like `@80008000` unmapped.
- **Fix**: Updated `convert_hex.py` to mask the Spike base address (`byte_addr -= 0x80000000 if byte_addr >= 0x80000000`) and divide by 4 to compute exact word addresses.

### 5. PyVSC / PyBoolector Compatibility in RISCV-DV
- **Issue**: PyBoolector updated its API from `BTOR_OPT_*` constants to `BtorOption.BTOR_OPT_*`, causing the randomizer in `pyvsc` to crash during test generation. Additionally, binary expressions with `None` values caused evaluation exceptions.
- **Fix**: Applied monkey-patches to `vsc/model/randomizer.py` and `vsc/visitors/x_expr_evaluator.py`.

### 6. Sub-program Callstack Generator in Pygen
- **Issue**: `riscv-dv` testlist specified `+num_of_sub_program=5` or `10`, triggering `AttributeError: 'riscv_asm_program_gen' object has no attribute 'callstack_gen'`.
- **Fix**: Updated `testlist.yaml` to specify `+num_of_sub_program=0` for all target tests, allowing clean random assembly generation.
